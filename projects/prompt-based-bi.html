Data Product Architecture · 02

Prompt-Based Business Intelligence System

A natural-language query engine over relational SQL databases, bridging non-technical executive teams with immediate, audited database reporting and chart visualizations.

Aniket Thakur · Product Builder & Data Analyst · Natural Language · SQL · Data Science
Text-to-SQL Data Analytics SQL Databases BI Reporting

1. The Operational Challenge: Analytics Turnaround Lag

In growing technology and fintech startups, product managers and executive leaders require immediate quantitative answers to operational queries: *\"What was the default rate on 36-month two-wheeler loans last month in Delhi compared to Mumbai?\"* or *\"Which affiliate partner is driving the highest volume of drop-offs during KYC verification?\"*

Because querying relational production databases requires structured SQL and familiarity with database schemas, every question turns into a Jira ticket queued for the data engineering team, creating multiday turnaround delays for routine business decisions.

2. Architectural Design & Security Sandboxing

[ Executive Natural-Language Prompt ]
               │
               ▼
   [ Schema Metadata Injector ] ───► Sanitized DB Table & Column Schema
               │
               ▼
   [ LLM Translation Engine ] ────► Generate Audited Read-Only SQL Query
               │
               ▼
   [ Security Validator & Linter ] ─► Block DROP/DELETE/INSERT/UPDATE;
               │                     Enforce Strict Limit Clamping & Timeouts
               ▼
   [ Read-Only Sandbox Execution ] ─► Execute Against Analytics Replica
               │
               ▼
   [ Dynamic Visualizer & Summary ] ─► Render Clean Data Table & Plotly Charts

Security & Determinism Guardrails

  • Zero Write Access: Strict read-only database user credentials and AST (Abstract Syntax Tree) SQL linting prevent any accidental state mutation or data leaks.
  • Schema Embedding: Embeds table relationships, foreign key constraints, and business acronyms into the context prompt to ensure exact join logic across normalized databases.
  • Explainable SQL: Outputs the executed SQL alongside the visual chart so analysts can verify query logic before relying on calculations.

3. Results & Business Value

Self-Serve Non-technical teams explore database metrics independently
0 Zero SQL queries written by executive leadership
100% Read-only enforcement across all query sandboxes

The system democratized access to data, freeing data engineers from answering repetitive operational requests while empowering leadership with immediate insights.
